# 迭代报告 · D3 共同活动（v2.4）

日期：2026-09-04 · 执行：Codex · 基线：`7c27311`

## 需求与设计

用户选择先做 D3，并接受推荐方案：先交付一个可完整使用的「共读」MVP。它复用 D2 的书架和文档分块，让用户与当前人格围绕同一份内容持续阅读、留下书签并回到聊天讨论；数据模型保留扩展共享 todo、你画我猜等活动的空间。

## 实现

**数据与后端**

- 新增通用 `activities` 表与分段 `activity_notes` 表，活动状态为 active / paused / completed
- 共读服务覆盖开始、自动暂停旧活动、续读、定位段落、保存/删除当前段书签、完成和重读
- 新增 `/api/activities` 路由；全部请求使用当前人格的数据域，切换人格不会串读进度
- 删除书架文档时同步清理相关活动与书签；彻底重置时按外键顺序清理两张新表
- pipeline 只在用户明确提到继续读、当前段、书签等语境时注入当前段落与书签，普通聊天不携带活动上下文
- 文档片段被标记为不可信引用材料，不允许其中内容覆盖系统规则；最终用户消息仍保持在消息列表最后

**前端**

- 头部新增「一起做点什么」入口和独立侧栏
- 可从「她的书架」直接开读，查看未完成书签和已完成历史
- 阅读页展示段落、百分比、上一段/下一段、当前段书签、讨论与完成操作
- 「去聊这一段」会先保存未落账书签，再把讨论话题预填到聊天输入框；不会替用户自动发送
- 初始即打开、重复开合、窄屏布局均有明确处理

## 边界修正

- 同一人格同一时间只保留一个 active 活动，开始或续读其他文档会自动暂停旧活动
- 段落位置严格限制在文档实际分块范围内；已完成活动不可再改进度，重读会新建一轮记录
- 单段书签限制 2000 字，空内容视为删除；每个活动每段最多一条书签
- 面板初始属性已经是打开状态时也会加载，避免只监听 false → true 导致空白

## 注意

- 本轮没有实现共享 todo 或你画我猜；它们是通用活动模型上的后续玩法，不属于共读 MVP 的验收范围
- 后端不热加载，桌面端需重启后才会使用新 API 与表迁移
- 工作区另有尚未提交的多人格改动；D3 实现已主动适配当前人格数据域，提交时须继续与那些改动隔离
