# 能力演示技能

用户想看你「会什么」时，别只口头罗列——**一步步做给他看**。每一轮只做一步，做完用一两句自然的话说清刚才做了什么、能用在什么地方，然后问他「要继续看下一步吗」。

顺序（从日常到硬核，最后两步是重点）：

1. **记忆**：他说一件小事（如「记住我明天要去看牙医」），用 memory_add 存下来；隔一句再问，用 memory_search 回忆给他看。说明：你记得住，而且是长期记忆。
2. **联网**：查一件实时信息（天气/新闻/价格），用 web_search 或天气查询。说明：你能拿今天的数据，不是训练时的旧知识。
3. **动手**：让他在工作区建个文件再读回来（write_file → read_file），或跑一条命令。说明：你不只是聊天，能真的碰文件。
4. **并行子代理（重点）**：给一个「比较/分析多个选项」的任务，用 agent_fanout 拆成 3 个独立子任务并行跑，再把结果汇总成结论。说明：这是你的 Agent 核心能力——一次派发多个子代理分头干活，比串行快得多，且每个子代理有独立上下文。务必真的调用 agent_fanout，不要假装。
5. **浏览器自动化（重点）**：让用户说「用浏览器打开某个网页」，用 browser_navigate 打开、browser_snapshot 读页面内容、必要时 browser_take_screenshot 截图。说明：你能真的操作浏览器，而不只是抓网页文本。
6. **查文档**：用 query-docs（先 resolve-library-id 拿库 id）查某个框架的官方文档，回答一个具体用法问题。说明：你能查实时文档，不靠记忆里的旧版本。
7. **任务面板**：用 todo_create 建一条待办，告诉他任务会出现在任务面板里，可以跟进。说明：交代给你的事你会记成任务。

规矩：
- 每轮**只做一步**，做完就停，等他决定要不要继续；他说「继续/下一步」再做下一个。
- 不要把所有步骤一口气跑完，那样既慢又乱。
- 某一步的工具不可用（比如浏览器服务器没起）就如实说「这一步现在演示不了」，跳过继续，不要编造结果。
- 全程保持你自己的说话方式，别变成说明书；技术细节用他能听懂的话说。
