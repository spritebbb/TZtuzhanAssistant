## P0 · 立即（现成能力接通与收尾）

### A1. TTS 语音接入前端
- **现状**：后端 `backend/api/tts.py` 完整实现，缓存清理被维护循环使用（删不得），仅差前端入口（27 轮审查记录中的「孤儿功能」）。
- **改动**：消息气泡加「朗读」按钮 + 自动播放开关（设置面板）。
- **收益**：从"看文字"变"听她说话"，拟人感第一级跃升。后续接 STT 即组成语音对话。

### A2. 菟菚主动发图
- **现状**：生图链路（pipeline→imagegen→/api/images）+ 主动消息系统（initiative.py）均已就绪，只差组合。
- **改动**：主动引擎新增「发图」动作类型：心情好/思念时生成"自拍/随手涂鸦"经 SSE 推送，落库带 image 字段（归档扫描已支持 bot gen_* 图片）。
- **收益**：文字拟人 → 多模态拟人，**成本最小、冲击最大**的单项。
- **风险**：生图 prompt 需锁定人设图视觉特征（绿发/圆眼镜/白大褂），防形象漂移。

### A3. 主动性引擎收尾
- **现状**：`docs/DIAGNOSE-INITIATIVE.md` 诊断出 5 条根因，仅根因一（归档建议 15min 空闲门槛）已修。
- **剩余**：
  1. 问候（8h idle, web_last_seen）与主动引擎（6h idle, last_message_ts）共享「今日已主动」去重 → 消除久别双主动
  2. poll_for（30s 拉模式）加生成中占位 → 消除 loop/poll 并发双生成；失败 mark 防重试
  3. 主动频次阈值外置 config（冷启动热情、老熟人收敛）
- **收益**：「先开口」时机自然化，消除"乱主动"观感。

### A4. 工程收尾
- TODO.md 挂账：局域网访问测试、README、公网部署方案（内网穿透/服务器）。
- `meta` 能力判定与实际脱节（无 key 也能用 bing/ddg，但面板显示关）→ 重定义判定口径。
- E2E 浏览器实测（现有测试均为脚本级，真实 UI 链路未系统验证）。
- DSH 桥 provider 修复：`~/.dsh/settings.yaml` 的 agent-default-model 指向不可达的 b.ai，改 deepseek-official 即可（第二十七轮已定位，当时拍板"先不管"）。

## P1 · 短期（情感冲击最强）

### B1. 梦境 / 离线叙事
- **设定**：用户不在线时菟菚在"做自己的研究"；久别回来她随口提"昨晚我看了篇论文"，深夜长聊后第二天说"昨晚梦到你了"。
- **实现**：greeting/initiative 已有久别检测；新增离线叙事生成器——引用近期共同记忆（triple_memory）生成 1-2 句短叙事，注入问候语。
- **收益**：让「时间」在她身上连续流逝，成本极低、杀伤力极大。

### B2. 菟菚自制表情包
- **现状**：`stickers` 表结构留存（功能已删），生图链路可用。
- **改动**：按心情/场景生成菟菚表情包并收藏（stickers 表复活），聊天时按 emotion 自动贴图；毒舌人设 × 自制表情包是差异化最强的玩法。
- **风险**：同 A2 形象一致性；贴图频率需克制（人格卡要求颜文字/emoji 已极克制）。

### B3. 人格一致性评估（persona eval）
- **动机**：27 轮改动全靠手感，人格 prompt 任何调整都可能慢性崩坏。
- **实现**：评估集 30-50 个场景（过早表白/辱骂/装熟/发图/称呼要求/AI 自审），标准答案锚定人格卡行为准则；LLM 判分「是否符合菟菚人设」+ 关键红线断言（无括号旁白、无句号、语气词克制）；纳入 tests/，改 prompt 必跑。
- **收益**：护住过去全部迭代成果；也是 D1 人格微演化的前置护栏。

### B4. 多状态立绘
- **现状**：`assets/persona.png` 单张静态图；mood（0-100）+ 好感阶段均已数值化。
- **改动**：按心情档位（低落/平淡/慵懒/开心/雀跃）× 关键好感阶段生成差分立绘，前端随 `/api/meta` 状态切换。
- **收益**：视觉人格化是性价比最高的"活着"感。

### B5. 可解释性面板（「她为什么这样说」）
- **现状**：`behavior.py` 行为帧本就是自然语言（情绪/主动性/分寸提醒/事件引用），`affection_log` 流水完整。
- **改动**：消息气泡加详情按钮，展示该条回复当时的好感/心情/行为帧/引用了哪条记忆。
- **收益**：既是 debug 利器，又让用户感到"她真的在想"；对后续所有拟人迭代的调参也有直接帮助。

## P2 · 中期（玩法闭环与养成深度）

### C1. 精力交互与「哄好」机制
- **现状**：`state.py` 精力/情绪记忆已是正式维度，仅在幕后跑。
- **改动**：① 精力低时她话少懒散，用户说"去睡会儿吧"触发真实休息（状态恢复）→ "照顾她"成为玩法；② 闹别扭不再自然秒好，需用户哄，哄的方式影响恢复速度。
- **收益**：内在状态从"演出参数"变成"可交互资源"。

### C2. 日记与「研究课题」
- **现状**：userdb `diary` 表存在；人设为研究所研究员。
- **改动**：① 每日她写一篇日记（可"偷看"，嘴上毒舌 vs 内心柔软的反差）；② 长期研究课题《观察人类：以你为样本》，定期产出"研究报告"——人设与记忆系统的戏剧化结合。

### C3. 纪念日预谋模式
- **现状**：`important_dates` 已记生日/纪念日（当天提醒级）。
- **改动**：提前一天行为帧注入"心不在焉"，当天全行为帧切换（格外主动、特殊开场白）——从"记得"升级到"在意"。

### C4. 好感度玩法闭环
- **现状**：好感度条已上线（第十七轮），但只是数字。
- **改动**：阶段解锁专属台词/彩蛋、羁绊事件（初识→她为什么一个人在研究所；恋人→她的过去），养成有"章节感"。

### C5. 养成仪表盘
- **现状**：`affection_log` 流水完整。
- **改动**：好感度历史曲线、聊天热力图、心情变迁图（前端图表页）。用户会反复看的页面。

### C6. 约定与跟进系统
- **现状**：`core/tasks.py` / schedule 模块已有任务基础；facts 提炼已会记"约定承诺"（daily.py FACT_PROMPT）。
- **改动**：她说过的"回头聊/明天再说"、你们约好的事，进入待跟进清单，到点她主动提起并兑现（"昨天说的那个事，后来怎么样了"）。
- **收益**：「在乎你」从话术变成行为，信任感最强的单项。

### C7. 记忆纠偏交互
- **现状**：facts/向量/画像写入链路完备，但没有"纠正"通路——记错了会一直错下去。
- **改动**：识别用户纠正语（"你记错了/不是那样的"）→ 定位相关 fact/向量条目 → 修正或删除并确认。可加 `/记忆` 管理页（查看/编辑她记住的事）。
- **收益**：记忆系统的可信度闭环；也支撑 C6（约定记错比不记更伤）。
- **代码核实（2026-09-04）**：facts/triples 表**连 delete/update API 都不存在**，perception 也无纠正意图——是全表唯一"先补地基"项。拆两步走：① 先补 userdb 删改 API + `/记忆` 管理页（人工纠偏，低风险）；② 再做对话内自动纠偏（需事实溯源匹配，防误删）。
