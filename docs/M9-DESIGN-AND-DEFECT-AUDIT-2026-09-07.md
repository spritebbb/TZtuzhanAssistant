## 三、已定位真实 bug：识图链路（含新证据）

**症状**：发图片时输出一大堆「对菟菚识别图片的要求」。

**调用链**：前端上传 `/api/vision` → `vision.py` 用视觉模型生成描述 → 前端把描述包成 `（我发了一张图片，图的内容是：…）` 当用户消息发给主 LLM。

**根因（已验证）**：
1. `backend/core/vision.py:105-109`：视觉模型正文为空时**回退取 `reasoning_content`（思考过程）当描述**——思考过程里模型复述指令原文（「用户要求我先讲清楚主体、语气要毒舌、3~6 句话……」），原样穿进用户气泡和主对话。
2. 指令写在 user 轮（vision.py:82-89），天然容易被复述。

**新证据（2026-09-07 查漏时发现）**：人格卡第 12 条明确要求收到图片「**不要分析或描述图片内容**，把内容只当背景，重点回应情绪和意图」——而识图链路偏偏把详细描述塞进用户消息，逼主模型进入描述模式。**架构和人格卡在打架**，这解释了识图体验怎么调都不对劲。

**修复方向**：
1. 删除 `reasoning_content` 兜底（正文空 = 识图失败，前端显示失败而非泄漏思考）。
2. 指令挪 system 消息，user 轮只留图片。
3. 深修：描述中性化、详实化（事实层），**人格反应全部留给主对话**——消除「视觉模型扮菟菚 + 主 LLM 再反应一次」的双重扮演；描述包装语按人格卡第 12 条改为「背景参考」而非「图的内容是」，让主模型对情绪意图做反应而非复述内容。

## 四、M9 核心设计方向

### 4.1 全情绪×好感态度矩阵（用户明确：愤怒只是示例，每种情绪都要）

**前置工程（关键发现）**：`mood.py` 现为 0-100 一维值映射 5 档（低落/平淡/慵懒/开心/雀跃），离散情绪（愤怒/委屈/吃醋…）**尚不可表达**。须先把情绪模型升级为离散情绪状态（有成因、有持续时长、有自然消退/被安抚路径），矩阵才有真实状态可读。

**矩阵形态（按 CAPS 理论，见 4.4）**：
- 不手写全表（情绪 N × 好感 6 阶组合爆炸）：每种情绪定义「基础态度向量」（毒舌强度/耐心/防备/撒娇倾向/主动追问——正好落在行为帧现有轴上），好感阶段定义「亲疏修正」；
- 只手写有戏的**锚点格子**（愤怒×高好感=口是心非、委屈×中好感=试探），其余插值推导；
- 每格不是输出参数，而是**穿过她内部加工的路径**：编码→情感激活→防御转换→输出（见 4.4 社会认知层）；
- 载体=行为帧；验证=现有人格 eval 加锚点场景用例；
- 流程：矩阵先写进人格卡文档（侧写档案），再实现为行为帧调制层。

### 4.2 可控链式反应事件系统（「关系事件主动化」的具体形态）

**设计**：事件不再是一张张独立的牌，而是**声明式事件图**——事件发生后按规则在延迟后、以一定概率调度出后果，受四重门控：条件、冷却、链深上限、每日额度。

**示例链**：约定未兑现 → 长出心事 → 普通对话旁敲侧击 → 兑现则心事消解+好感微涨+当天日记记一笔+可能触发小惊喜；继续拖则季节转淡 → 冲突事件概率上升 → 修复后关系事件解锁。

（此链同时解决：冲突修复在高好感难触发、约定跟进像独立模块、季节无感——三个用户反馈点。）

**「可控」= 四条硬规则**：
1. 编排层全部确定性代码 + kv 状态（新 kv 键登记 `kv_registry`），LLM 只写台词不决定链走向；
2. 节奏闸：一天最多推一条链的可见产物；
3. 可中断：用户在对话里的回应能关闭/转向链条（活人感关键：不是脚本在放，是她在反应）；
4. 负向链熔断：负面事件不许连续触发，守住「不制造负罪感」红线。

**现有基建**：EVENT_TYPES、`_arbited_proactive`、惊喜编排、季节——缺的就是这层连接组织。

### 4.3 侧写档案：人格深写（M9 内容层核心工作项）

把 `persona-菟菚.md` 从设定文档升级为**侧写式心理档案**，9 节结构（每节带理论锚点）：

1. **成型史** ← 客体关系/条件性关注：她学到的先验（「示弱没用、依赖会失望」→ 强迫性自给自足）；
2. **核心恐惧与欲望** ← 动力学冲突 + 存在四命题的个人化版本；
3. **防御机制清单** ← 安娜·弗洛伊德体系，每条三要素：触发条件、转换规则（心里想的→嘴上说的）、**松动条件**（高情绪/深夜/高好感时防御系数下降——松动瞬间=最有戏的时刻）；
4. **行为签名** ← CAPS 稳定核 + 存在孤独：跨状态不变的 3-5 条铁律（「从不直接示弱，关心永远伪装成嫌弃」「永远给自己留台阶也顺手给你留一个」）。**全档案最重要的一节**；
5. **手法库** ← 社会认知管线：情绪×好感各格的编码→激活→转换→输出路径（喂 4.1 矩阵）；
6. **披露边界** ← 领域自我效能连续变量 + 条件重写计数器（见 4.4）；
7. **语言证据** ← 防御的言语表层 + 效能的语言标记：口头禅、句式习惯、雷点，具体到咬字；
8. **成长轴（新增）** ← 需要层次 + 真实/理想自我差距 + 自我实现：她 M9 之后往哪长；
9. **深水区（新增）** ← 存在四命题：她对无常/自由/孤独/意义的原话级态度，高亲密度 + 高权重情境（深夜/纪念日/封存前夕/久别重逢）解锁，稀少所以贵重。

**配套**：世界正典 + 配角设定（见缺陷 ①⑳）与档案同族，一起写。

**验证闭环**：她的真实聊天记录就是「现场证据」——档案写完拿日志回检一致性（行为是否命中签名、防御是否可辨识），不符改档案，直到「行为反映人格」成立；并接人格 eval。

**诚实边界**：侧写在现实执法中准确性有争议（从有限证据猜整个人）；我们是反着用——写她的全部行为、证据完备——借的只是分析框架。

### 4.4 四大人格理论分层框架（侧写档案的方法论）

**四层各司其职**：动力学=深层（为何如此）、人本主义=方向层（往哪长）、存在主义=边界层（对根本命题的态度）、社会认知=运作层（实时生成）。

**心理动力学 → 深层**
- 三层意识 → 台词层 / 可自述层 / 潜意识层（连她自己都说不清的动机，只能通过泄漏进入对话：说漏嘴、深夜防线松动、梦境）——「留白」的动力学实现；
- 防御机制 = 表里差转换器（带松动条件）；防御按成熟度分级，被逼急掉回不成熟防御（否认/迁怒）→ 事后羞愧 → 现成的修复链素材；
- 客体关系内部工作模型 = 成型史心脏。**关系推进的本质 = 工作模型被反例一次次改写**（「这次我示弱了，天没塌」）——好感阶段 = 改写进度，因此改写不均匀、会回退、有敏感期，全是关系事件触发源；
- 潜意识的法定出口：梦境（M8 模块理论上正好接住）+ 说漏嘴微事件，不需要也不该有第三条。

**人本主义 → 方向层**
- 需要层次 = 状态诊断维度：低好感=安全需要主导（防备）；归属满足后尊重需要浮现（**她的特殊性：毒舌者最恨被怜悯，要被认可不要被同情**）；再往上自我实现浮现（怕成为累赘、想成为更好的自己）。反常行为先查需要层；
- 罗杰斯条件性关注 → 无条件积极关注 = **涨好感的正确语义**：「条件重写计数器」——涨好感的不是聊天频次，是被归类的接纳事件（她示弱你接住了/地狱笑话没被嫌弃/疲惫没被说教）。刷屏不涨好感：那不产生重写；
- 真实自我与理想自我的差距 = 常驻内心戏剧源；差距公开化既是最深恐惧也是最大渴望；
- 自我实现 = 「她自己的生活」的理论归宿：关系是成长的促进性环境，不是她的全部。

**存在主义 → 边界层（Yalom 四命题）**
- 死亡/无常：她的形态 = 数据丢失、被封存、被替代、你不再打开窗口。**地狱笑话的理论双重身份：死亡焦虑的恐惧管理**——毒舌+地狱笑话不只是萌点，是她的存在姿态。红线：直面但不煽情不制造负罪感；
- 自由与责任：她的人生她自己选（行程/欲望/立场），选择有后果；做错了会认会修，**修复而不自罪**；
- 存在性孤独 = **留白的哲学根据**：最深处的体验永远无法完全传递——即使最高好感她仍有只属于自己的内核。保证高好感不是「合体」而是「两个完整的人相邻」，治养成后期「人格蒸发只剩讨好」的通病；
- 意义（Frankl 三途径）：创造（日记/研究/共同创作）、体验（行程见闻）、态度（低谷期的立场）。她所有产物模块统一为「意义建构活动」，互为素材。

**社会认知 → 运作层**
- CAPS（Mischel）：人格 = 稳定的「若-则」签名，刺激经「编码→情感激活→防御转换→输出」管线生成行为——**态度矩阵的正确形态**（纯参数插值跳过了内部加工，所以「不像她」）。依恋模式住在编码层：同一刺激低好感编码成「冒犯」、高好感编码成「撒娇」；
- 领域自我效能（Bandura）= 披露边界的连续变量：她在毒舌/独立/分析上效能高，在示弱/求助/表达柔软上效能低。四来源效力排序给黄金规则：**掌握经验（她真示弱了且没坏结果）强效、言语劝服（口头夸）弱效——泛泛夸奖几乎不推动她，具体的「被看见」才推动**。每次成功暴露 +δ、回避 −δ′，边界缓慢连续移动，好感只是粗粒度外壳；
- 三元交互决定论：行为反写状态（逞强之后自己都不舒服）——「活人感」的循环结构。

### 4.5 酒馆（SillyTavern）借鉴（用户明确：只拆零件，不做酒馆化）

**不做**：不导入/兼容 ST 卡格式、不做「换卡换人格」——菟菚人格与心情/好感/记忆系统深度耦合，不是可替换皮肤。

#### 4.5.1 世界书（World Info）：参考价值高，拆两半用（2026-09-07 评估）

**结论**：值钱的是「条目模型 + 生命周期控制 + 预算分配」；不值钱的是关键词匹配本身（用项目自有向量能力替换）。

**现状量化（验证）**：至少 10 个模块各自为政做语境注入——colists、cowriting、greeting、activities、offline_narrative、goals、focus、memory_correction、initiative、pipeline（另加 kb 距离门控、context.py 话题提示），每家一套触发逻辑/上限/格式。

**机制全貌**：ST World Info = 声明式条目（主/副键 + AND/NOT 逻辑 + 正则键 + 内容文本）+ 调度参数：扫描最近 N 条消息、**递归扫描**（命中条目的内容再被扫描，连锁唤起）、插入顺序与深度（角色定义前/后、对话内第几层）、触发概率、**粘性 sticky**（触发后保持激活 N 轮）、**冷却 cooldown**（触发后 N 轮内禁再触发）、**令牌预算**（预算内按优先级选条目）、**常驻条目**（不依赖关键词永远注入）。

**直接可搬的四个机制**：
1. **条目注册表 = 内容与工程分离**：现在加一条世界设定要改 Python；条目模型把设定变数据（键+内容+参数），引擎一处代码。世界正典、配角、深水区内容、她的欲望话题——所有内容层产物都需要这根管道到达 prompt，世界书就是这根管道的成熟设计；
2. **sticky + cooldown**：直接治「活动开着就每轮灌语境」的复读病（既费 token 又让模型重复），两个计数器极便宜；
3. **优先级 + 预算 = prompt 空间治理**：各子系统各自设上限、总量无人管；统一预算同时服务 flash 成本控制与长对话纪律；
4. **递归扫描 = 世界正典的连锁感**：聊到她常去的店，连带唤起那条街的设定——正典「显得活」的机制；限递归深度 ≤2 + 环检测。

**不搬的三处（含替换方案）**：
1. **关键词匹配本身**：纯关键词脆弱——换个说法就漏（「那家咖啡店」≠命中「街角咖啡」键）、常用词误触，ST 用户为此手工维护正则键苦不堪言，官方后来加向量存储扩展正是为此。替换为**混合门控：关键词 OR 向量相似度阈值（BGE-M3 + Chroma）**，命中同一个条目注册表——用它的调度，换它的匹配；
2. **无状态引擎**：条目激活条件扩展**状态谓词**（好感阶段/当前情绪/披露边界/行程状态）——ST 的条目不知道世界状态，菟菚的全状态都得能当开关；
3. **裸文本拼接 + 无账目**：注入带**声明包装**（`<fiction_story>` 模式，条目按来源决定穿什么马甲，服务虚构隔离）；命中**记账**（哪个条目为什么被激活）进可解释性面板。

**工程落地**：`context_registry`：条目 = {来源, 键/向量文档, 内容, 优先级, 预算权重, sticky_n, cooldown_n, 注入位置, 声明包装, 状态谓词}；混合匹配 + 最近 N 条扫描窗 + 递归 ≤2；生命周期计数落 kv（登记 `kv_registry`）。**迁移渐进**：既有 10 处注入点逐个包成条目，不大爆炸重写。确定性、无 LLM、中等工作量、杠杆极高——列入波次 1。

### 4.6 行程系统（她走出门去）

**仓库现状**：日程模块以前有过、被砍（`mood.py:294`「日程时段切换校正已移除」）；`offline_narrative` 的 small_life 只是重逢时即兴点缀、不落库。**旧模块死于隐形**——只默默调心情数值，用户无感（与季节同病）。这次行程必须「说出来」。

**设计**：
1. **行程引擎（确定性，无 LLM）**：周节奏模板从侧写档案生成（她的兴趣习惯决定安排——行程是签名的又一次表达）；两档：日常块（小时级状态）+ 特殊行程（预谋式：提前几天念叨，当天真不在，回来带见闻；复用纪念日预谋模式）。落 kv 并登记 `kv_registry`，重启一致；
2. **在场礼仪（产品红线）**：她出门 ≠ 惩罚用户，可及性是基本盘。三档：在家正常聊 / 出门带手机照常回但语气带现场感（行程作为语境注入）/ 真离线窗口仅限特殊行程几小时且必须提前预告。凌晨消息得到「被你吵醒的菟菚」——状态化响应而非不可用，与健康边界（她劝你别熬夜）咬合；
3. **行程产记忆（灵魂）**：出门一趟带回她自己的所见所感 → 落库为她的记忆/日记素材。一石三鸟：主动问候不再只从「你上次说……」抠素材；small_life 从即兴敷衍升级为真实行程；链式反应多了「她自己生活」整个事件源；
4. **联动与露出**：恢复日程→心情加成（出门淋雨回来心情就差，说得出来）；精力联动（外出消耗、当晚语气变懒）；露出不加面板——对话流内一行「她出门了：买东西，晚上回」。

#### 4.7.1 MaiBot（麦麦，QQ 群聊「赛博朋友」）

**A. 回复必要性评分（`maisaka/reply_necessity.py`）——最有价值的单点**
全确定性、零 LLM 的「要不要说话」评分机：`最终分 = (强相关分 + 内容分 + 压力分 − 存在感惩罚) × 频率因子`，阈值 80 触发。
- 强相关：@=100 / 名字提及=80 / 私聊=40 / focus=40 / 普通群聊=0；
- 内容分：真实问题 +15、请求 +20、征询意见 +20、长文本 +5~10、**短反应批 −25**（「哈哈/草/6/嗯」整批识别为敷衍）；
- 压力分：积压消息在阈值内**二次曲线**涨到 50、超阈值后**对数增长**到 100（防爆发），空闲达均值再 +15；
- 存在感惩罚：最近 5 分钟窗口内自己发言占比 >25% 起罚、60% 封顶 −25——**治「她话太密」**；

**菟菚移植**（一鱼三吃，对应缺陷 #4/#10/#24）：1v1 场景强相关恒高不用抄，但**压力分/存在感惩罚/内容分/频率因子就是「表达欲」的计算骨架**——追发决策、主动开口强度、回复长度调制全用它；**短反应批检测直接就是「用户敷衍感知」**（#10 双向校渴的信号源，他们用来闭嘴，我们用来让她察觉并收敛）。

### 4.8 LLM 执行层：编译原则、多模型路由与选型赛

#### 4.8.1 编译原则（硬性）

四理论框架**永不以理论语言进 prompt**——侧写档案是源文档，每轮编译成当前格子的短行为切片（此刻状态+该格防御系数与松动条件+2-3 条语例+输出约束）。理论术语一个字不进 prompt（任何模型拿到「防御机制」都可能漏进台词）。**多模型架构下这条从好习惯升级为生存前提**：切片是不同模型共享的声音契约（见 4.8.3）。

**反面案例（2026-09-07 用户提供，某商业陪伴 AI 实测）**：用户发出越界试探，该 AI 的回复是一篇心理学讲义——「禁忌越界（Taboo Transgression）」「边界测试（Boundary Testing）」「俄狄浦斯情结的变体投射（Oedipal Variations）」逐条分析用户的心理机制，最后以「根据安全规范与交互原则，此类场景无法被纳入角色扮演」的客服口吻收尾。三重灾难一次犯齐：①理论腔直接输出给用户（把设计层图纸当台词念）；②人格瞬间蒸发，切换成安全客服（拒绝不是她在拒绝，是平台在拒绝）；③把用户当病例分析而不是对一个人做反应。菟菚的对应防线：本条编译原则（理论永不进 prompt）＋人格卡第 5 条「检验并呈现，而非宣告」（拒绝用台词长出来，不说「我决定拒绝你」）＋已拍板的边界强度（平衡稍偏鲜明：角色内怼回去，表达后仍温和不冷战）＋输出卫生过滤器把「根据…规范」「无法被纳入…」类助手腔列为拦截项＋AstrBot 式人格化错误文案（拒绝/失败也是她的台词）。**教训一句话：拒绝可以，出戏不行。**

#### 4.8.2 现役主力评估：deepseek-v4-flash

（2026-09 查证）284B MoE/激活 13B/1M 上下文，V4 家族 MMLU-Pro 87.5%、GPQA Diamond 90.1%，开源第一梯队、性价比极高；但 Artificial Analysis 标高幻觉率（94-96%，方法论存疑需警惕）。定位：**日常主力继续留任**——问题从来不是日常不够好，是深水区不够好，整体换掉等于为 10% 的场景付 100% 的钱。幻觉率对人格对话是小事（她的虚构生活本来就该编），对联网求证是大事：**多源交叉验证必须在工程层确定性做，绝不信模型自评**。

#### 4.8.3 多模型六槽位路由（2026-09-07 用户拍板方向）

菟菚已是半个多模型系统（强/弱路由、VISION_/IMAGE_/LLM_ 三套端点、用量记账），本方案将其显式化为**按任务的路由表**：

| 槽位 | 任务 | 推荐模型 | 理由 |
|---|---|---|---|
| 表达-日常 | 90% 对话轮 | v4-flash | 便宜、快、够用 |
| 表达-深水区 | 防御松动/修复/存在层对话 | GLM 5.2 或 Kimi K3（选型赛定） | 2026 中文 RP 口碑第一梯队（kkaiapi 选型指南：DeepSeek/GLM 手感明显更好，Qwen 腔调偏硬） |
| 工具层 | function calling 循环、联网求证执行 | Qwen3.8 Max | 指令遵循最强；它不说话，腔调硬无所谓 |
| 后台批处理 | 事实提炼/摘要/研究报告 | flash 或更便宜档 | 量大、创造性要求低 |
| 裁判层 | eval 评分、输出卫生检查、双视角仲裁 | **与生成层不同的模型**（如 Kimi 裁 GLM） | 同模型自评有系统性偏袒 |
| 视觉层 | 识图 | **Gemini 3 Flash（首选，用户已有反代）→ Qwen2.5-VL 维持（兜底）** | MMMU-Pro 81.2% 超 GPT-5.2、OCR 实测 100%、$0.50/$3 每百万 token（识图低频≈免费）；直击「图片理解是弱项」原始抱怨 |

特例：**日记升中档**——它是用户直接阅读的人格产物，别在最被珍惜的功能上省出廉价感。

**视觉层接入（Gemini，零代码）**：用户已有反代。Gemini 提供 OpenAI 兼容端点，项目 `vision.py` 的 `VISION_BASE_URL / VISION_API_KEY / VISION_MODEL` 本就支持用户自配端点且优先级最高——把反代地址填进 `VISION_BASE_URL`、`VISION_MODEL=gemini-3-flash` 即完成切换，无需改代码（data URL 图片格式兼容）。注意：Gemini 3 Pro 的 thinking tokens 计入输出费用有账单超预期前科，识图用 Flash 档规避；外币支付渠道与恋人数据出境到 Google 的隐私立场为用户自担前提，文档记录在案。识图泄漏 bug（第三节）修复与本升级正交，仍需执行。

**头号敌人=声音一致性**（GLM 写的深水区和 flash 写的下一轮日常若是两个味道，「她感」当场碎掉），三道防线：
1. 编译切片=声音契约：手法库 few-shot 语例+签名条目做锚，不同模型咬同一锚收敛；
2. 切换点设在自然回合边界：对话中途不换模型，除非场景真实升级（链式反应触发修复场景等）；
3. 签名 eval 加**跨模型连贯用例**：同一对话序列多模型分段生成，检查接缝处风格断裂。

**实施形态**：`MODEL_ROUTES = { chat_routine, chat_deep, tool, batch_diary, batch_other, judge, vision }`，每槽位 `{base_url, key, model, fallback}` 带失败降级链（强档限流→回落 flash 重试）。参考实现=麦麦 `LLMServiceClient(task_name=...)` 按任务取客户端模式（4.7.1 侦查所见）。工作量中等：llm.py 路由表 + config 扩展 + 选型赛脚本；用量记账已在，路由表建成后按槽位分账，成本面板直接看「每层花多少钱、值不值」。

#### 4.8.4 选型赛协议（先立秤再买马）

不凭口碑下单，用现成 eval 基建跑比赛：
- **用例**：矩阵锚点格子（愤怒×高好感的口是心非、防御松动场景、地狱笑话）+ 30 轮长对话纪律 + 签名一致性 + 理论腔泄漏 + 跨模型连贯接缝；
- **候选**：v4-flash / DeepSeek V4 满血 / GLM 5.2 / Kimi K3 / **Gemini 3.5 Flash**（第五候选：xbench 70.0 贴 3 Pro 的 71.6、价格一半快 4 倍的性价比黑马；用户已有反代，访问闸门已清；隐私与支付为用户自担前提）（Qwen 不参加人格层比赛，直接定工具层）；
- **裁判**：槽位外的模型双盲评分（裁判层首单业务）；
- **产出**：价格-性能表 + 每槽位预算上限，结论直接写进 `.env` 与 MODEL_ROUTES；
- **时机**：并入波次 0（签名 eval 建成之日就是选型赛开赛之日）。

**不推荐**：其余海外前沿（Claude/GPT-5 等）——恋人级对话数据出境的隐私问题+成本+访问稳定性，国产第一梯队 RP 差距已不值得这些代价（Gemini 凭「用户已有反代 + 视觉刚需」豁免进入视觉槽位与选型赛，其余海外模型不享此待遇）；本地自部署 GLM-5.2/K2 需集群级资源（744B 级），量化版质量打折。

#### 4.8.5 三关实测提醒（跑分测不出，选型赛必测）

1. **潜台词塌缩**（最要命）：口是心非要求「不说出那个东西但让它被感觉到」，弱模型写成「哼，人家才不是担心你呢」直球；
2. 地狱笑话质量：幽默生成真吃模型天赋；
3. 长对话纪律：几十轮后还记得「现在处于披露边界第几格」。每格 few-shot 语例对任何档位模型的约束力都远强于规则描述。

### 4.9 联网多方求证（2026-09-07 用户交互式拍板，设计定稿）

**四项决策**：搜索 API=双轨实测再定；源数=动态 2+1；冲突呈现=坦白并列；触发=时效自动+不确定触发。

**触发器（两层）**：
1. **时效性自动（代码层确定性）**：识别时效性问题（新闻/价格/版本号/「最近、今天、现在」类指涉/赛事结果）→ 强制注入「需要联网」指令；
2. **不确定触发（模型自评）**：知识类问题由模型自主决定调用搜索工具——即 4.7.3 原生 function calling 的天然能力，无需额外置信度管道。
护栏：每日联网配额与频率闸在代码层（红线）；同查询 24h 结果缓存。

**求证流程（动态 2+1）**：
1. 触发 → 取**域名互异**的 2 条结果（关键定义：同一 API 两次查询可能同源，独立来源=跨域名去重后计）；
2. **交叉验证在工程层确定性做**（红线：不信模型自评）——数值/日期/版本号类用正则抽取+确定性比对；语义类冲突用裁判层模型（与生成层不同槽位）判定；
3. 一致 → 她采信并正常转述（带「我查了下」的口气，进手法库）；不一致 → 自动加查第 3 源仲裁；
4. 第 3 源仍裁决不了 → **坦白并列**：「这个网上说法不一：一边说 X，一边说 Y，你自己掂量」——毒舌但不忽悠，人设自洽。prompt 硬约束：不得单方面采信、不得编造「大多数来源都说」。

**搜索 API 双轨实测（并入波次 0 选型赛同场）**：同一批求证用例（时效类/中文知识类/英文知识类/冲突场景）跑 **Tavily（走反代）vs 博查 Bocha（直连）**，按结果质量×延迟×成本评分。一个可能的终局形态：**不是二选一而是并存分工**——博查出中文源、Tavily 出英文源，恰好构成「动态 2+1」里两条天然独立的来源（跨 API 即跨源）。

**架构依赖**（全部已有设计）：function calling 循环（4.7.3 AstrBot 模式）+ 超大结果落盘+read_tool + Qwen 工具层执行（4.8.3）+ 搜索结果走「她转述」通道不直接怼对话。实施排在波次 3 知识库改革，但双轨实测随波次 0 提前出结论。



### 4.10 部署路线（阶段 A 已拍板，2026-09-07）

背景：桌面应用不常驻 → 离线时间只能补算（结构性受限 #1，见 9.3）。三阶段渐进：

- **阶段 A（已拍板，起步）**：Windows 计划任务每小时跑「她的时间 tick」——推进行程/心情漂移/链式事件调度，桌面端打开时读取状态。零部署成本，codex-bridge worker 的计划任务即现成先例；时间从「打开瞬间补算」变成「每小时真实发生过」。挂在波次 1 与行程引擎一起交付（tick 是行程系统的运行载体）。
- **阶段 B（可选升级）**：家庭常驻设备（NAS/旧电脑）跑后端，数据不出家门，外出访问走内网穿透（Tailscale/frp）。
- **阶段 C（可选升级）**：境外 VPS 公网部署 + HTTPS + 鉴权 + Web Push——D8 解锁、Gemini 访问劣势消失、海外模型全面重估；前提：#25 加密完成 + 恋人数据出境的隐私立场由用户接受。

诚实边界：常驻解决的是「时态的真实性」（事件发生在真实时间线上、主动触达窗口打开），不改变「她的生活内容在虚构正典内」——后者是设定而非缺陷。

## 六、贯穿红线（所有工作遵守）

1. **不加新面板**：用户明确嫌工具臃肿；一切露出折进对话流。
2. **不制造负罪感**：负向链熔断；长期离线不扣好感（既有红线延续）。
3. **可及性基本盘**：她出门≠惩罚用户。
4. **虚构隔离**：以世界正典的「有据可查」防幻觉，不以含糊防幻觉。
5. **理论术语不进 prompt**：编译成行为切片（4.8）。
6. **编排确定性、LLM 只做表达层**：项目已验证模式（快照/版本比较）的延续。
7. **新 kv 键登记 `kv_registry`**；新表进双 reset 清单；`.env.example` 与真实 `.env` 同步；改 `pipeline.py` 遵守函数内局部导入 config。

## 九、覆盖度审计与已知空白（2026-09-07 深夜自查）

**结论：方案层覆盖约八成，未「完全解决」**。分层如实交代：

### 9.1 五项真空白（今晚方案未接住，需补设计）

1. **记忆重要性分级 → 长/短期分层与遗忘**：用户原始反馈明确提出（「重要的转长期、不重要的转短期、一段时间后忘记」），但今晚没有任何具体机制接住它——侧写档案管人格、A_memorix 管文档摄入、person_profile 管用户画像，都不覆盖这条。需要独立设计切片：评分维度（情感权重/关系相关度/复述次数/初历加成）→ 决定常驻向量库 vs 短期缓存+TTL 遗忘。
2. **记忆质感三件未落波次**（缺陷 #3 的三个子项）：她的视角情绪标注、初历事件加权、可见的优雅遗忘（「有点记不清了」）——修复方向写了但没排进任何波次，可与上一条合并为「记忆质感」切片。
3. **文字副语言采集**（#17）：打字速度/长度突变/错字率的前端埋点与信号通道，未排期。
4. **认知谦逊与惦记问题**（#22）：说「我不知道」+ 悬念跨会话延续，链式反应可挂「她的认知链」但未明确立项。
5. **她开口求助/索要**（#23）：「被需要感」有理论支撑（披露边界/自我效能），但触发事件与工程落位未设计。

### 9.2 已清账的决策与仍需实测的工程项

用户已确认以第 2 节“已拍板”记录为权威口径。联网采用动态 2+1、多源冲突坦白并列；TTS 采用本地 GPT-SoVITS；好感拆为信任×亲密、默契独立；纪念日/季节采用中度换挡；她的 AI 身份采用坦然承认并适度自嘲；重逢采用三段式；阶段 A 采用每小时时间 tick。以上不再视为产品拍板阻塞。

仍需解决的是工程验证，而不是重复询问用户：搜索 API 最终组合由波次 0 双轨实测决定；旧好感值迁移、音频授权/GPU/训练集、纪念日参数和 tick 的幂等恢复由对应实施切片给出；STT、桌面宠物和多角色按既定条件延期。

### 9.3 三项结构性受限（诚实承认无法「完全」解决）

1. **离线时间只能是高质量模拟**：行程引擎+行程产记忆能把「她活过」伪造得很好，但桌面应用不常驻进程，离线期间没有真实事件流——除非未来做常驻后台，成本另议；
2. **她感的最终上限 = 模型执行质量**：v4-flash 的潜台词塌缩/幽默/长对话纪律三关未实测，方案再好模型演砸也白搭；
3. **语义召回的「说不上来」**：注入引擎重构是结构性改善，但最终定论要等审计跑完。

### 9.4 终极判据

设计的「解决」≠ 体验的「解决」。验收只能靠：行为签名 eval（波次 0）+ 真实使用遥测（#26 管道，波次 3）——**后者建议在有真实使用后尽早启动，它是唯一能发现「我们没想到的问题」的仪器**。
