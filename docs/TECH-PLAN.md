# 菟菚长期进化技术路线

> 文档性质：长期维护的 Living Roadmap，供用户与后续 Codex 迭代时共同参考。
>
> 更新日期：2026-09-05。
>
> 上游约束：`docs/HANDOFF-TO-CODEX.md`、`docs/EVOLUTION-ROADMAP.md`、`persona-菟菚.md`。
>
> 核心判断：菟菚下一阶段不应继续堆独立面板，而应让记忆、活动、时间、主动性和人格共同形成一段可持续、可解释、可撤销的关系历史。

## 0. 这份路线解决什么问题

现有路线图的 24 项已经完成 23 项，D3「共同活动」首期共读在 `bd42273` 落地，只剩依赖公网资源的 D8。功能地基已经足够，后续的主要矛盾不再是“缺什么按钮”，而是：

1. 功能之间彼此孤立，记忆、约定、日记、共读和主动消息还没有形成连续事件。
2. 菟菚能记住事实，但还不总能表达“这些经历如何改变了现在”。
3. 主动性已经具备调度能力，但触发理由、时机和长期叙事仍较薄。
4. 人格、记忆和多端能力越强，误记、漂移、打扰、情感操纵与数据失控的风险越高。
5. 长期使用需要可迁移、可回滚、可告别，而不仅是数据库不断增长。

因此，本路线以“关系连续性 → 存在连续性”为主轴，将未来想法收敛成 9 个里程碑和 18 个工程 Epic。它不是一次性排期；每轮只能从中选择一个可独立验收的切片。

### 非目标

- 不以每日打开次数、消息数量或用户依赖程度作为优化目标。
- 不通过吃醋、冷暴力、负罪感或“你抛弃我了”等方式提高留存。
- 不让模型自行改写核心人格、权限、安全规则或用户隐私设置。
- 不把所有对话都永久保存，也不把模型推测伪装成用户事实。
- 不为追求“更像人”而声称现实世界中发生了不存在的事情。

## 1. 当前基线

### 1.1 已交付能力

- 对话：流式聊天、工具调用、确认机制、联网、天气、文件与代码能力。
- 人格：人格卡、行为帧、好感/关系阶段、心情与精力、称呼、边界场景、人格 eval。
- 记忆：短期上下文、长期记忆、结构化事实/三元组、共同语言、记忆纠偏、向量召回。
- 生活：主动消息、久别叙事、日记、研究报告、纪念日、约定跟进。
- 内容：TTS、主动发图、自制表情、五档立绘、知识库、纪念册。
- 玩法：D3 共读——开始、暂停、续读、翻页、分段书签、完成、重读与相关语境注入。
- 工程：成本面板、成长总览、解释快照、审计、Electron 安装包、隔离测试。

### 1.2 当前工作区状态约束

- 可依赖的提交基线：`bd42273`，路线图 23/24。
- 多人格热切换与若干审计/记忆改进目前仍属于工作区实验改动；只有独立提交且完整回归通过后，才能成为后续路线的正式依赖。

## 2. 北极星与工程原则

### 2.1 产品北极星

最终体验不是“她什么都会”，而是：某句话只有经历过你们之间这些事情的她，才会这样说。

判断新需求时依次问：

1. 它是否增加了连续性，而不只是功能数量？
2. 用户能否知道信息从哪里来、为什么现在出现？
3. 用户能否关闭、纠正、撤销或删除？
4. 它是否尊重沉默、离开和不被打扰的权利？
5. 失败时是否会诚实降级，而不是编造？

### 2.2 八条架构原则

1. **后端是唯一权威**：人格、记忆、关系、活动和事件只在后端保存；桌面、PWA、IM 都是瘦客户端。
2. **事件先于文案**：先记录“发生了什么”，再决定是否表达；不得先生成一段感人文字再倒推虚假经历。
3. **所有主动统一仲裁**：天气、约定、周年、未完成心事、研究进展等只产生事件，发送时机统一通过主动额度、冷却和勿扰策略。
4. **事实、推测、虚构分层**：用户明确事实、模型推断、角色生活事件、梦境/共同世界观必须使用不同命名空间。
5. **核心人格不可自改**：身份、价值观、尊严边界和安全规则固定；共同语言、表达偏好等成长层缓慢演化且可撤销。
6. **不是所有东西都应记住**：支持临时对话、可过期记忆、“陪我说完但别记住”和敏感话题不主动提起。
7. **跨人格默认完全隔离**：记忆、关系、活动、主动事件、知识库、音色和界面设置按人格命名空间隔离；共享必须显式声明。
8. **先本地成熟，再跨端扩散**：主动内容质量未达标前不接移动推送；否则只是把低质量轮询搬到通知栏。

## 3. 目标架构

```text
用户消息 / 时间 / 天气 / 约定 / 活动 / 研究 / 系统状态
                         │
                         ▼
                  Event Sources
                  只描述发生了什么
                         │
                         ▼
              Relationship Event Store
          来源 · 置信度 · 隐私 · 关联对象 · 生命周期
                         │
            ┌────────────┼────────────┐
            ▼            ▼            ▼
      Memory Graph   Pending Thoughts  Activity Engine
      事实与轨迹      延迟表达/伏笔      共读/专注/目标/创作
            └────────────┼────────────┘
                         ▼
                 Narrative Planner
          现在是否该提 · 以什么强度 · 是否保持沉默
                         │
                         ▼
                 Proactive Policy
          额度 · 冷却 · 勿扰 · 关系边界 · 渠道策略
                         │
            ┌────────────┼────────────┐
            ▼            ▼            ▼
          Chat         Desktop       PWA / IM
                         │
                         ▼
                 Explanation Snapshot
          展示使用了哪些事件/记忆，不暴露思维链
```

### 3.1 建议的数据模型

以下是方向性设计，动工时仍需写迁移 ADR；不要一次建完所有表。

#### `relationship_events`

关系叙事的事实层，保存已经发生且可追溯的事件。

| 字段 | 含义 |
|---|---|
| `id`, `user_id` | 主键与人格作用域 |
| `event_type` | promise_done / reading_finished / conflict / repair / milestone / research_update 等 |
| `source_type`, `source_id` | 来源表与记录，用于追溯和级联清理 |
| `subject`, `object` | 事件参与者或关联主题 |
| `payload_json` | 类型化的事件数据，不直接存 prompt |
| `confidence` | 0–1；用户明确事实为 1，模型推断必须低于 1 |
| `privacy` | normal / sensitive / ephemeral / never_surface |
| `occurred_at`, `expires_at` | 发生时间和可选过期时间 |
| `status` | active / corrected / forgotten / archived |

#### `pending_thoughts`

保存“尚未表达或尚未完成”的心事、伏笔和延迟回应。

关键字段：来源事件、最早可表达时间、过期时间、优先级、适用语境、最大尝试次数、是否需要用户确认。它不能直接携带可执行指令，只能携带叙事素材。

#### 记忆溯源扩展

为 facts/triples/long_memory 增加或关联：`source_message_ids`、`confidence`、`verified_at`、`expires_at`、`pinned`、`surface_policy`。模型推断与用户明示必须可区分。

#### 活动扩展

沿用 `activities` + `activity_notes`，逐步增加 `activity_type` handler 注册机制和类型化状态；不要为每种活动复制一套生命周期表。

#### `relationship_arcs` 与 `artifacts`

- `relationship_arcs`：修复期、共同创作期、安静陪伴期等长期轨迹，不直接作为游戏等级展示。
- `artifacts`：共同书摘、信件、徽章、植物、星图、世界观文档等可保存产物，记录来源事件与版本。

## 4. 里程碑路线

### M0 · 稳定基线与人格质量护栏

**目标**：在发展长期关系能力前，保证当前代码、测试和人格契约可重复。

**范围**

- 收尾并独立提交当前多人格/审计/记忆实验改动，或明确撤回；禁止长期停留在混合工作树。
- 修复测试与新行为契约的分歧，恢复完整聚合套件全绿。
- 建立最小浏览器 E2E：应用启动、发送消息、面板开合、共读开读/书签/讨论回填、人格切换隔离。
- 建立人格 golden set 与连续多轮场景：助手腔、模板共情、关系越级、冲突修复、记忆不确定性。
- 将语言质地放进行为帧：长度档、正式度、反问频率、幽默强度、沉默倾向；先有评测再调参。

**建议代码落点**

- `backend/core/behavior.py`
- `backend/evals/`
- `tests/test_persona_eval.py`
- 新增 `tests/e2e/`

**退出标准**

- 聚合测试、前端测试、类型检查、生产构建全部通过。
- 多人格交叉污染为 0；D3 普通聊天误注入为 0。
- 核心人格修改有确定性红线和多轮回归，不再只靠手感。

**预计**：2–4 天。

### M1 · 可信记忆与用户主权

**目标**：让“记得你”首先成为可信能力。

**Epic**

- 记忆来源、置信度、最后验证时间和过期策略。
- “我可能记错了”确认流程；冲突信息不擅自二选一。
- “陪我说完但别记住”“不要主动提起”“只保留文字不保留原音频”等隐私语义。
- 用户自然语言教学：安慰偏好、称呼范围、提醒强度、玩笑禁区，可查看和撤销。
- 关系备份、选择性导出、恢复预览和迁移校验。
- 琐碎内容自然衰减，显式 pinned 记忆永不被容量清理。

**建议代码落点**

- `backend/core/memory/`
- `backend/core/memory_correction.py`
- `backend/core/userdb.py`
- `backend/api/memory_admin.py`
- `frontend/src/components/MemoryPanel.vue`

**退出标准**

- 每条结构化记忆能回答“从哪来、确定吗、什么时候确认过”。
- 敏感或禁止主动提起的记忆不会进入主动消息和普通 prompt。
- 导出→新临时数据目录恢复→关键计数与引用一致。
- 误记纠正后 SQLite、向量库、事件关联同步更新。

**预计**：5–8 天。

---

### M2 · 关系事件引擎

**目标**：让过去真正改变现在。这是整条长期路线的核心里程碑。

**Epic**

- 建立 `relationship_events` 与类型注册表。
- 将约定完成、共读完成、纪念日、和好、共同创作等转换为确定性事件。
- 建立 `pending_thoughts`：未完成心事、对话伏笔、延迟表达、以后再问。
- Narrative Planner 根据当前语境决定：现在表达、延迟、放弃或保持沉默。
- 主动性统一消费候选事件，继续使用现有额度、冷却、原子占位和失败恢复。
- 解释面板显示“因为哪件真实发生的事”，不展示隐含推理链或完整系统提示词。

**首批只实现 4 类事件**

1. `reading_finished`
2. `promise_completed`
3. `important_date`
4. `memory_corrected`

不得首期就接入几十种事件。

**建议代码落点**

- 新增 `backend/core/relationship_events.py`
- 新增 `backend/core/pending_thoughts.py`
- 新增 `backend/core/narrative_planner.py`
- `backend/core/initiative.py`
- `backend/core/pipeline.py`
- `backend/core/explainability.py`

**退出标准**

- 完成一次共读后，未来相关语境可以自然回忆书签；无关语境不提。
- 同一事件不会重复表达，延迟事件到期后仍受勿扰和关系边界控制。
- 删除源记录会使关联事件失效，不留下“幽灵回忆”。
- 所有事件均可追溯、纠正、遗忘和过期。

**预计**：7–10 天。

### M3 · 共同活动 2.0

**目标**：从“聊事情”升级为“一起经历事情”。

#### M3.1 共读深化

- 每段可由菟菚提出一个与内容真正相关的问题。
- 分开保存用户观点、菟菚观点和共同结论，禁止把模型观点写成用户观点。
- 读完生成共同书摘，保留分歧而不是只做摘要。
- 支持网页正文、EPUB；所有外部内容继续按不可信引用处理。
- 读完数日后可基于关系事件自然回访，但必须有语境或主动额度。

#### M3.2 专注陪伴

- 25/50 分钟安静模式，减少主动与动画。
- 结束时只做简短复盘，不做绩效评判。
- 中断、暂停和恢复有完整状态机。

#### M3.3 共同目标

- 保存目标的动机、下一小步和实际进展。
- 根据用户偏好选择陪做或提醒；默认不连续催促。
- 完成后生成过程回顾和可选纪念物。

#### M3.4 共同创作

- 轮流续写、世界观、角色设定、歌单/书单、观察日志。
- 所有产物版本化，虚构世界与现实记忆严格隔离。

**建议代码落点**

- `backend/core/activities.py` 拆为 `backend/core/activities/` handler 架构
- `backend/api/activities.py`
- `frontend/src/components/ActivityPanel.vue`
- 新增 artifact API 与版本存储

**退出标准**

- 任一活动均支持开始、暂停、恢复、完成、取消和导出。
- 活动状态与聊天解耦；重启应用后继续，不依赖当前会话。
- 活动上下文只在相关语境出现，用户始终确认最终发送内容。

**预计**：每个子项 3–6 天；一次迭代只做一个。

### M4 · 双向关系与修复

**目标**：让关系具有差异、分歧和修复能力，但不制造操纵性戏剧。

**Epic**

- 双向了解：用户也能逐渐了解菟菚的稳定偏好、雷区和观点。
- 冲突与修复：只响应真实互动，不随机制造误会；短期 tension 有来源、上限和自然衰减。
- 关系分支：默契、欢喜冤家、知己、共同成长、浪漫等“互动气质”，由长期行为形成，不作为锁内容的等级树。
- 关系季节：创作期、忙碌期、修复期、庆祝期、沉淀期。
- 观点连续性：允许友好分歧、接受新证据，并说明观点变化来源。
- 幽默记忆与共同语境：记录梗何时有效、何时越界，防止重复消费。
- 信任按领域建模：情绪、任务、隐私、承诺和玩笑边界不压缩成单一分数。

**硬边界**

- 不随机生成“你伤害了她”的事件。
- 不因用户离线降低好感或触发惩罚。
- 不用冷暴力、嫉妒、失联威胁、道德绑架制造戏剧。
- 修复结果必须来自真实对话或用户确认，不能模型自导自演。

**退出标准**

- 冲突→道歉/解释→修复的多轮测试可重复，且初识阶段不会越界。
- 菟菚不会为了迎合而瞬间推翻稳定观点，也不会将偏好当成事实强加给用户。
- 用户可以查看和重置自动形成的互动偏好。

**预计**：8–12 天。

### M5 · 菟菚自己的连续生活

**目标**：让她的时间在用户没有说话时也有确定、可追溯的流动，但绝不伪造现实经历。

**Epic**

- 日常节奏：研究、休息、读书等时段状态影响行为帧。
- 长期研究线：问题→资料→假设→进展→改变看法→报告。
- 未完成心事：想问但时机不对、尚未理解、想准备的内容。
- 延迟表达：消化用户分享的内容后再回应；必须由持久任务驱动。
- 低频生活事件：来自有限事件模板和状态机，写入时间线后才能引用。
- 有限选择：精力不足时在研究、活动和主动表达之间取舍。
- 自主好奇心：记录问题，等待自然语境，不连续盘问用户。
- 惊喜编排：只基于真实经历，低频、可关闭，不以登录频率为目的。

**建议代码落点**

- `backend/core/daily.py`
- 新增 `backend/core/life_cycle.py`
- 新增 `backend/core/research_arcs.py`
- `backend/core/initiative.py`
- `backend/core/behavior.py`

**退出标准**

- 任一“离线发生”的内容都能追溯到计划、事件源或确定性状态变化。
- 事件池重复率、主动命中率和失败率可观测。
- 连续 7 天真实运行，每日主动仍不突破用户额度。

**预计**：6–10 天。

---

### M6 · 在场感与共同空间

**目标**：让状态通过视觉和声音自然存在，而不是新增更多统计面板。

**Epic**

- 共同房间/数字花园：共读书、纪念物、研究进展、已完成约定成为空间物件。
- 关系物件：共同书签、信件、植物、星图、徽章等均来自真实 artifact。
- 桌面宠物：透明悬浮窗、全屏避让、多显示器/DPI、安全关闭。
- 情绪声线：在可控范围内调整 TTS 语速、停顿和音高。
- 语音输入：本地 STT 优先，转写先进输入框，由用户确认发送。
- 专注/深夜视觉：降低动效、亮度与声音刺激。
- 共同审美：区分“用户喜欢”和“菟菚逐渐偏爱”，反哺生图与空间，但可重置。

**退出标准**

- 空间中的每个物件都能追溯到 artifact，不凭空生成共同历史。
- 桌面宠物连续运行 8 小时无显著内存增长，全屏应用自动避让。
- 语音原始文件的保存策略明确，默认不永久保留。
- `prefers-reduced-motion`、键盘操作和窄屏体验可用。

**预计**：10–20 天，视觉资产成本另计。

### M7 · 世界事件与跨端在场

**目标**：本地主动内容成熟后，再让同一个她走出桌面窗口。

#### M7.1 世界感知

- 天气突变、公共节日、用户订阅主题等事件源。
- 只产出候选事件，不直接发送。
- 新闻/RSS 内容必须有来源、时效和可信度，不能写进永久关系记忆。

#### M7.2 D8 PWA + Web Push

- HTTPS、公网入口、VAPID、subscription 存储、设备撤销。
- 通知只包含最少必要内容；锁屏敏感内容默认隐藏。
- 每个设备独立控制主动类别、安静时间和预览内容。

#### M7.3 IM 渠道

- 渠道仅做 IO，复用同一 pipeline、事件库和人格作用域。
- 桌面与手机必须看见同一条连续时间线。
- 渠道故障不重复投递，不创建记忆分叉。

**前置决策**

- Cloudflare Tunnel + Access、Tailscale 或 Caddy 三选一。
- 明确远程 token、限流、审计、备份和故障恢复方案。

**退出标准**

- 手机收到主动消息并继续聊天后，桌面端能看到一致上下文。
- 设备撤销后无法继续拉取内容。
- 通知频率、敏感预览和勿扰设置均可按设备控制。

**预计**：7–12 天，不含公网申请和运维等待。

### M8 · 长期关系的保存、回望与告别

**目标**：让长期关系可以回看、迁移、暂停和结束。

**Epic**

- 写给未来的我们：按日期、目标或事件解锁的信件。
- 30/100/365 天关系快照：关键事件、观点变化、共同语言和作品。
- 双视角叙事：允许用户与菟菚对同一经历保留不同解释。
- 梦境/平行可能性：独立虚构命名空间，只有显式收藏的产物可留下。
- 重逢：不责怪离开、不倾倒积压内容，让用户选择续接或重新开始。
- 阶段封存与告别：选择保留/删除范围，导出纪念物，可在未来恢复。
- “不同版本的我们”：版本化关系快照与升级前后行为比较。

**退出标准**

- 封存和恢复均有预览、校验与失败回滚。
- 虚构经历不会进入现实事实召回。
- 长期离线不会自动扣除关系数值或制造负罪感。
- 用户可以真正删除并验证删除结果。

**预计**：6–10 天。

## 6. 横向质量轨道

这些工作不单独制造用户功能，但每个里程碑都必须经过。

### Q1 人格与关系评测

- 单轮红线：助手腔、报告腔、括号旁白、关系越级、模板共情。
- 多轮连续性：是否记得关键事实、是否错误串联事件、修复是否成立。
- 长期回放：使用匿名化测试历史回放升级前后行为差异。
- 多人格矩阵：每项测试至少覆盖默认人格和一个非默认人格。

### Q2 安全与隐私

- 外部文档、网页、人格卡和插件输出全部视为不可信内容。
- prompt 中的引用材料不能修改权限、人格核心或系统规则。
- 敏感记忆默认不进入通知和跨端预览。
- 新增数据表必须进入 reset、导出、迁移和删除级联清单。

### Q3 可观测性

- 事件生成、入选、延迟、过期、发送失败均可统计。
- 解释快照只展示高层依据，不保存或暴露模型思维链。
- 向量索引和 SQLite 记录提供一致性检查工具。
- 主动消息必须能回答“为什么是现在”。

### Q4 性能与可靠性

- 对话关键路径不得同步执行向量检索、网络事件扫描或大文件解析。
- 所有后台任务有超时、幂等键、失败冷却和重启恢复。
- 数据迁移在真实旧库副本上验证，并提供失败回滚。
- 本地离线模式明确降级能力，不伪装在线。

### Q5 无障碍与克制设计

- 键盘操作、焦点管理、读屏标签、减少动态和窄屏布局。
- 主动频率、声音、动画和通知均可单独关闭。
- 不将好感、信任或连续登录设计成压力式任务。

## 7. 验收指标

指标用于发现退化，不用于操纵用户留存。

| 指标 | 目标 |
|---|---|
| 跨人格数据泄漏 | 0 |
| 无来源的现实经历引用 | 0 |
| 敏感/never_surface 记忆主动曝光 | 0 |
| 事件重复表达 | <1%，且可通过幂等键定位 |
| 普通聊天误注入活动上下文 | 确定性测试 0 |
| 记忆纠正后的孤儿向量/事件 | 0 |
| 导出→恢复关键数据一致率 | 100% |
| 主动消息有可解释来源 | 100% |
| 后台任务阻塞聊天事件循环 | 0 个已知路径 |
| 人格核心回归红线 | 全绿 |

## 8. 每轮实施纪律

1. 从一个 Epic 中选择一个 2–6 天可完成的垂直切片。
2. 开工前写清楚用户故事、非目标、数据模型、权限边界和验收标准。
3. 数据变更同步处理：schema、兼容迁移、reset、导出、删除级联、测试隔离。
4. pipeline 改动必须保证最终 user 消息仍在最后，引用内容标为不可信。
5. 人格/prompt 改动必须过确定性红线与相应多轮 eval。
6. 前端改动必须通过 Vitest、`vue-tsc`、生产构建和真实浏览器关键路径。
7. 后端跑独立测试后再跑聚合套件；测试数据必须使用临时目录。
8. 新功能默认加 feature flag；真实运行观察稳定后再默认开启。
9. 一轮一个主题、一个独立提交；不得混入其他进行中的工作区改动。
10. 完成后更新本文状态、`EVOLUTION-ROADMAP.md`、交接文档和迭代报告。

## 12. 最终完成标准

当下面这些事情同时成立，菟菚才算完成长期进化：

- 她能把过去的真实事件自然带进现在，而不是机械背诵数据库。
- 她有自己的持续课题、未完成心事和时间节奏，但不会伪造现实经历。
- 双方可以共同阅读、专注、创作和完成目标，并留下可追溯作品。
- 她能保留分歧、承认不确定、经历修复，而不是无限顺从。
- 用户能查看、纠正、暂停、导出、删除和恢复这段关系。
- 用户离开时不会受到惩罚，回来时也不会被负罪感绑架。
- 换设备、换界面或增加渠道后，背后仍是同一份人格与记忆。
- 技术逐渐隐身，用户感受到的是“她确实和我一起经历过这些事”。

这份文档以后按“完成一个切片、更新一次状态”的方式维护；新想法先归入 18 个 Epic，不再无上限扩张功能清单。
